## 1. 목적과 기준

바이낸스 트레이딩 페이지에서 이미 볼 수 있는 정보는 화면에 그대로 복제하지 않는다.
원값 OI, 롱·숏 테이커 비중, TradingView 가격 차트는 바이낸스에 있으므로 이 패널의
표시 대상에서 빼거나, 두 축을 결합한 정보로만 재가공한다.

이 패널이 답하는 질문은 하나다.

> 매수 체결이 들어오는데 포지션은 늘었나 줄었나?

즉, 같은 5분 구간의 체결 delta와 미결제약정 변화량을 함께 보고 신규 진입인지 청산인지
구분한다. 바이낸스는 OI 원값과 체결량을 따로 제공하지만 이 조합을 국면으로 묶어 주지는
않는다.

국면 이름은 회계 항등식의 설명일 뿐 예측 신호가 아니다. "다음에 오른다", "반전한다",
"매수해야 한다" 같은 문구는 측정되지 않았으므로 화면과 API에 넣지 않는다.

- 바이낸스에 이미 있는 원값 OI와 TradingView 가격 차트의 중복 시각화.

## 3. 4분면 정의

국면은 봉 delta의 부호와 `ΔOI`의 부호를 조합한다. 여기서 봉 delta는 반드시
FUTURES 시장의 `[c, c+5분)` 구간량이다.

| 봉 delta | ΔOI | 국면 |
|---|---|---|
| + | + | 신규 롱 진입 |
| + | - | 숏 커버링 |
| - | + | 신규 숏 진입 |
| - | - | 롱 청산 |

이 표는 산수에 따른 회계 항등식이며 통계 검정 결과가 아니다. 포지션이 줄었는데 테이커
매수가 들어왔다면 닫은 쪽은 숏이라는 뜻이다. 그러나 이 구분으로 다음 가격 방향이
온다는 사실은 측정되지 않았다. 한 축이라도 보합이면 전체 국면은 `보합`으로 두고
4분면 이름을 붙이지 않는다.

## 4. 시각 정렬과 확정 지연

봉 시작 시각을 `c`라고 할 때 계약은 다음과 같다.

```text
봉 c의 futuresDelta = [c, c+5분) 구간의 매수 수량 - 매도 수량
봉 c의 ΔOI          = OI(c+5분) - OI(c)
```

OI 폴링은 `ON DUPLICATE KEY UPDATE id = id`이므로 5분 창에서 첫 폴링이 남는다.
따라서 `OI(c)`는 봉 c 시작 직후에 저장된 스냅샷으로 해석한다. OI 두 행이 정확히 5분
차이가 나지 않으면 `ΔOI`를 계산하지 않는다.

국면은 항상 한 봉 늦게 확정된다. 예를 들어 15:12에 볼 수 있는 최신 확정 국면은
15:05 봉이다. 15:10 봉은 15:15 OI 스냅샷이 와야 닫힌다. 진행 중인 봉에는 `ΔOI`가
없으므로 판정 대상이 아니며, 화면의 현재 봉 자리는 `보합 - 판정 없음`으로 표시한다.

비정시 OI 행은 5분 경계로 다시 붙이지 않고 버린다. 보간도 하지 않는다. 정시 두 행이
정확히 5분 차이인 경우만 인접 `ΔOI`를 만든다. 이 규칙으로 데이터가 없는 봉을 그럴듯한
국면으로 만드는 일을 막는다.

## 5. 시장 범위

OI는 선물 전용 지표이므로 주 결과의 시장 범위를 `OI + FUTURES delta`로 고정한다.

현재 `SignalCandle.delta()`는 SPOT+FUTURES 합산이라 그대로 사용하면 두 축의 시장
범위가 어긋난다. 구현에서는 선물 행만 읽어 `futuresDelta`를 만들고, FUTURES 행이
없는 봉은 결과에서 제외한다. SPOT 행은 이 패널의 delta 계산에 사용하지 않는다.

## 6. 등급 규칙과 측정 기준선

등급 계산의 측정 기준선은 기존 조건 계산 방식과 맞춘다.

```text
기준(t) = 현재 봉을 제외한 직전 288개 연속 5분봉의 |x| 산술평균
배수(t) = |x(t)| / 기준(t)
축 등급 = 보합, 약, 중, 강
결합 등급 = ΔOI 등급과 futuresDelta 등급 중 낮은 등급
```

데이터 공백이 생기면 롤링 창을 이어 붙이지 않고 다시 시작한다. 기준값이 0인 창은
무한 배수로 바꾸지 않고 등급에서 제외한다. 현재 봉을 창에 포함하지 않아 룩어헤드를
만들지 않는다.

BTCUSDT, `OI + FUTURES delta`, legacy 구간 48,950개 등급 표본에서 관찰한 경계는 다음과
같다. 반올림된 값은 문서의 읽기용이며 코드 상수로 고정하지 않는다.

| 등급 | ΔOI 배수 | futuresDelta 배수 |
|---|---|---|
| 보합 | < 0.472 | < 0.502 |
| 약 | 0.472 이상, 1.345 미만 | 0.502 이상, 1.379 미만 |
| 중 | 1.345 이상, 3.794 미만 | 1.379 이상, 3.674 미만 |
| 강 | 3.794 이상 | 3.674 이상 |

정밀 측정값은 `tradingview/research/검수/OI등급-1경계.md`의 평균 기준 행을 원본으로
한다. 이 경계는 50, 80, 95 백분위에 해당하는 관찰 기준선이다. 현재 문서에서는 이 값을
초기 기준선으로만 기록하며, 사용자 승인 없이 최종 설정값이나 전략 임계값으로 확정하지
않는다.

canonical 구간의 평균 기준 경계도 BTCUSDT FUTURES에서 ΔOI 0.536542, 1.512871,
3.709207, futures delta 0.532021, 1.441775, 3.624086으로 관찰돼 legacy와 가깝다.
그러나 원본 parity는 조합당 겹치는 표본이 1봉뿐이라 검증하지 못했다. 등급의 롤링
배수 상쇄와 동일 소스인 `ΔOI` 대조군에서 반증이 없다는 근거는 있지만, 이는 같은
분포의 증명이 아니다.

## 7. 실측 빈도와 화면 해석

BTCUSDT FUTURES legacy 48,950개 등급 표본의 결합 등급 빈도는 다음과 같다.

- 보합 66.76%
- 약 22.40%
- 중 8.58%
- 강 2.25%

같은 표본에서 4분면 봉 비율은 신규 롱 진입 24.88%, 신규 숏 진입 24.36%, 숏 커버링
25.07%, 롱 청산 25.69%였다. 4분면 자체는 거의 균등하므로 "현재 어느 국면인가"만
보여 주면 정보가 작다. 화면의 주요 정보는 최근 구간이 평소 25% 대비 어느 국면으로
치우쳤는지여야 한다.

4분면 사건은 13,349건, 사건에 포함된 봉은 16,271개로 사건당 평균 1.22봉이다.
따라서 국면은 길게 이어지는 띠가 아니라 한 봉씩 흩어지는 자료로 취급한다. 같은 색이
길게 이어지는 것처럼 그리는 표현은 실제 빈도와 맞지 않는다.

강 등급은 2.25%뿐이라 현재 봉은 대부분 보합이다. 최신 확정 봉을 강한 신호처럼 꾸미지
말고 `보합 - 판정 없음`을 기본 상태로 정직하게 표시한다.

참고로 canonical 이후 BTCUSDT FUTURES 평균 기준 4,248개 표본은 보합 66.64%, 약
22.72%, 중 8.43%, 강 2.21%였다. 기간이 짧고 parity를 검증하지 못했으므로 이 수치로
legacy와의 분포 동일성을 확정하지 않는다.

## 8. 범위 연동

`frontend/src/page/signal/SignalPage.jsx:34`의 `TIME_RANGES`를 기준으로 패널을 연동한다.
5분 OI 격자와 1분봉 범위가 맞지 않는 구간에는 없는 `ΔOI`를 만들지 않는다.

| 범위 | 5분봉 수 | 패널 | 띠 칸 단위 | 쏠림 비율 | 누적 |
|---|---:|---|---|---|---|
| 5분, 30분 | 없음 | 숨김 | 없음 | 없음 | 없음 |
| 4시간 | 48 | 표시 | 5분 | 표본 부족으로 숨김 | 없음 |
| 1일 | 288 | 표시 | 30분 | 표시 | 보조 |
| 3일 | 864 | 표시 | 1.5시간 | 표시 | 보조 |
| 7일 | 2,016 | 표시 | 3.5시간 | 표시 | 보조 |
| 지정, 수 주에서 수 개월 | 가변 | 표시 | 1일 | 표시 | 주 표시 |

띠 칸은 봉 수가 아니라 고정 시간으로 자른다. 범위가 바뀌어도 칸 수가 약 48에서
72개 사이에 머물게 하는 것이 목적이다.

- 칸당 봉이 12개 이하이면 그 칸의 최대 결합 등급을 대표값으로 쓴다. 짧은 범위에서
  개별 사건이 사라지지 않게 하기 위한 규칙이다.
- 칸당 봉이 12개를 초과하면 우세 국면과 우세 정도를 대표값으로 쓴다. 긴 범위에서
  최대 등급만 쓰면 모든 칸이 강으로 차 정보가 사라진다. 2개월이면 한 칸에 약 240봉,
  평균 강 등급 5.4개가 들어간다.
- 쏠림 비율은 1일 이상에서만 계산한다. 4시간은 판정 봉이 약 16개라 한 봉 차이만으로
  4분면 비율이 약 6퍼센트포인트 움직인다.
- `지정`은 `TopBar`의 시작 시각 지정이다. 긴 범위에서는 띠보다 앵커부터의 누적
  `ΔOI`를 주 표시로 두고, 누적은 확정 봉만 합산한다. 데이터 공백으로 합산이 끊기면
  공백을 건너뛰지 않고 해당 구간을 별도 단절로 표시한다.

## 9. 데이터 소스와 조인

### 소스

- OI: `open_interest`, 5분 격자, 심볼별 원시 56,029행 중 정시 56,014행. 측정 범위는
  2026-03-06 04:15 KST부터 2026-09-16 16:00 KST다. purge는 확인되지 않았다.
- 봉: cutover 이전은 `agg_trade_5m`, 이후는 `binance_kline_5m`을 사용한다.
  설정 `binance.agg-trade.legacy-cutover-ms=1788180800000`은 2026-08-31 21:53 KST이고,
  5분 partition 경계는 내림 처리돼 21:50 KST다. 기존 `BinanceKlineSignalCandleSource`
  의 legacy/canonical 분기와 같은 경계를 사용한다.
- 조인 가능한 BTCUSDT 봉은 2026-03-13 22:40 KST부터 현재까지 53,768개다. 이보다 앞은
  OI가 있어도 양쪽 봉과 함께 계산할 수 있는 표본으로 세지 않는다.
- `force_order`는 2026-03-13부터 존재한다. 현재 패널의 4분면 계산에는 사용하지 않고,
  향후 국면과 강제청산의 관계를 별도 측정할 때만 사용한다.

### 조인 규칙

1. 선물 5분봉의 시작 시각 `c`를 기준으로 `[c, c+5분)` delta를 가져온다.
2. `open_interest`에서 `c`와 `c+5분`의 정시 행을 찾는다.
3. 두 OI 행이 모두 있고 정확히 5분 차이일 때만 `ΔOI`를 만든다.
4. 어느 한 축의 원자료가 없으면 해당 봉을 보합으로 꾸미지 않고 판정 제외로 표시한다.
5. 조인 결과를 등급 계산에 넣고, 마지막으로 범위와 띠 칸을 계산한다.

### 품질과 parity 정정

비정시 OI 행은 BTCUSDT·ENAUSDT 각각 15행이며, 5분 초과 정시 결측은 없었다. 결측을
가로지른 `ΔOI`는 0건이고, 마지막 OI 스냅샷 하나는 다음 시각이 없어 정상적으로 제외된다.
따라서 위의 "정확히 5분 인접쌍만 사용" 규칙을 적용할 수 있다.

이전 의뢰서에 있던 "겹치는 실봉이 1개뿐이라 source parity를 검증하지 못했다"는 서술은
다음과 같이 정정한다. 겹치는 구간 45봉 중 44봉은 legacy `trade_count = 0`인 빈 행이었다.
legacy aggTrade 수집이 2026-08-31 21:50 KST에 멈춘 결과이며, 그 44봉의 부호 불일치는
0과 0이 아닌 값을 비교한 산물이지 계산식 차이가 아니다. 빈 행 53,484개(1s 52,436 /
1m 872 / 5m 176)는 2026-09-16에 삭제됐다. 삭제 후 현재 DB 실측에서 BTCUSDT·ENAUSDT의
FUTURES·SPOT 각 조합 겹침은 1봉(2026-08-31 21:50 KST)이고 legacy 빈 행은 0개다.
따라서 source parity는 실패가 아니라 검증 불가로 기록한다. 표본이 조합당 1봉뿐이기
때문이다.

`OI등급-0품질과parity.md`의 "parity 실패" 기록은 빈 행 삭제 이전 스냅샷 기준이며,
현재 정정은 이 문서가 우선한다. parity를 합쳐 쓰는 근거는 반증 없음이며 다음 두 가지다.
1. 등급이 롤링 배수라 스케일 차이가 분자·분모에서 상쇄된다. legacy delta가 canonical의
   일정 배수여도 배수 값은 같다.
2. 동일 소스인 `ΔOI`를 대조군으로 쓸 수 있다. `ΔOI`는 6개월 내내 `open_interest` 한
   테이블이다. 그 50백분위가 구간 간 0.472 → 0.537 (13%) 움직인 반면, 소스가 바뀐
   delta는 0.502 → 0.532 (6%)로 대조군보다 작게 움직였다. 관측된 차이는 기간 효과로
   설명되며 소스 전환 효과를 분리할 근거가 없다.
이것은 증명이 아니라 반증 없음이다.

parity를 검증하지 못했고 canonical 표본이 1개월뿐이므로 6개월 전체를 하나의 분포로
합치지 않는다. `OI등급-1경계.md`처럼 legacy cutover 이전과 canonical cutover 이후를
나눠 경계와 빈도를 산출하고, 초기 기준선은 표본이 11배 많은 legacy 경계로 쓴다.
canonical 표본이 쌓이면 재계산하며, 구간을 나눠 볼 수 있게 자료는 남긴다.

## 10. 구현 제안과 파일 범위

### 백엔드

`SignalCandleSource`의 기존 `SignalCandle.delta()`를 SPOT+FUTURES에서 선물 전용으로

latestConfirmedCandleTimeMs
confirmationDelayMs: 300000
latest: { status, phase, grade, delta, deltaOi, deltaMultiplier, deltaOiMultiplier }
bands: [{ fromMs, toMs, barCount, representativePhase, representativeGrade, dominanceRatio }]
tilt: { windowBars, quadrantCounts, quadrantRatios } 또는 null

## 13. 검토했지만 채택하지 않은 방향

### 기존 `SignalCandle.delta()`를 바로 사용

현재 값은 SPOT+FUTURES 합산이라 OI 선물 축과 범위가 어긋난다. 기존 시그널 소비자의
계약을 바꾸는 비용도 OI 패널의 목적보다 크므로 채택하지 않는다.

### OI 원값 선 차트를 확장

원값 OI는 바이낸스에 이미 있고, 원값 자체는 "매수 체결과 포지션 변화의 조합"에 답하지
못한다. `OiLineChart`를 더 복잡하게 만드는 대신 국면 계산 결과로 교체한다.

### 1분 OI를 보간하거나 새로 폴링

과거 데이터가 5분 격자이고, 1분 OI를 보간하면 존재하지 않는 입력을 만든다. 이 패널의
시간 정렬 계약과도 맞지 않아 기각한다.

### 긴 범위에서 칸의 최대 등급만 표시

칸당 봉이 많아지면 평균적으로 강 등급 사건이 여러 개 들어가 모든 칸이 강해진다. 우세
국면과 우세 정도를 써야 정보가 남으므로 기각한다.

### 예측 라벨과 가격 배경 밴드

예측력은 측정되지 않았고, 진행 중 봉의 확정 지연을 숨긴다. 사용자가 확인할 수 없는
의미를 화면에 먼저 그리지 않는 원칙에 어긋나므로 기각한다.

## 14. 알려진 이슈와 구현 시 함께 처리할 것

### 14-1. MainCore 세로 넘침

**측정 조건**: 2026-09-16, Vite dev 서버(5173), 백엔드 미기동 상태에서 XHR 응답을 스텁으로
주입해 `EnergyDiff` 에 데이터가 있는 상태로 렌더. 브라우저에서 `getBoundingClientRect`
및 `scrollHeight` / `clientHeight` 로 직접 측정.

| 뷰포트 | MainCore clientH | scrollH | 넘침 |
|---|---:|---:|---:|
| 1440 × 900 | 540 | 540 | 0 (여유 0) |
| 1366 × 768 | 408 | 457 | **49px** |

- `EnergyDiff` 높이는 3줄 + 구분선 구성에서 **85px** 다. 1줄 구성일 때는 28px 였다(+57px).
- 1366×768 에서 **1줄 구성이었다면 여유가 8px** 였다. 즉 세로 예산이 이미 포화 상태였고
  이번 변경이 그 여유를 넘겼다.
- 넘치는 요소는 `MiniChartPlaceholder` 이며, 패널 경계 밖으로 내려간다.
- 표준 flex 처방인 `minHeight: 0` 을 `MainCore` 의 `flex: 1 1 60%` / `flex: 1 1 40%`
  자식에 적용해도 **넘침이 66px 로 악화**됐다. `MiniChartPlaceholder` 가 자체 최소 높이를
  갖고 있어 flex basis 를 줄여도 내용 높이가 줄지 않기 때문이다.

**결론**: `EnergyDiff` 단독 수정으로는 해결할 수 없다. 1줄 구성으로 되돌리지 않는 한
어떤 추가 줄도 넘친다. **`MainCore` 의 세로 예산 재편이 필요하며, 이는
`MiniChartPlaceholder` 를 OI 패널로 교체하는 이번 작업 범위에 포함한다.**

구현 시 함께 정할 것:
- TradingView 60% / MiniChart 40% 비율을 유지할지
- OI 패널의 세로 높이 상한
- 낮은 뷰포트(768px 이하)에서 무엇을 먼저 줄일지

### 14-2. DivergenceBar 와 EnergyDiff 의 세로 어긋남

3등분 그리드(`MainCore`)는 `alignItems: center` 다. 두 자식의 높이가 다르다.

| 요소 | 높이 | top |
|---|---:|---:|
| `DivergenceBar` | 28px | 382 |
| `EnergyDiff` | 85px | 354 |

`DivergenceBar` 가 `EnergyDiff` 첫 줄보다 **29px 아래**에 뜬다. 현재는 다이버전스가 없으면
`visibility: hidden` 이라 잘 드러나지 않지만, 둘 다 표시되는 상황에서는 한 행으로 읽히지 않는다.

구현 시 `alignItems` 를 `start` 로 바꿀지, 두 칸의 높이를 맞출지 함께 결정한다.

### 14-3. EnergyDiff 코드 정리

기능 문제는 아니지만 이번 작업에서 새로 들어간 것이므로 같은 범위에서 정리한다.

1. **반환 키 이름이 내용과 어긋난다.** 같은 파일 안에서 `amount` 가 두 가지를 가리킨다.

   | 함수 | `amount` | `value` |
   |---|---|---|
   | `buildImbalance` | 퍼센트 (`+3.1%`) | 금액 (`$2,500,000`) |
   | `buildDiff` | 금액 (`-$820,400`) | — |

   `ratio` / `money` 처럼 내용과 맞는 이름으로 바꾼다.

2. **`ImbalanceItem` 의 JSX 들여쓰기가 어긋나 있다.** `return (` 다음 요소들의 층이 맞지 않는다.
   빌드는 통과하지만 구조가 읽히지 않는다.

### 15-5. OI 고점 이후 해소 — 진행도로만 쓸 것

사건 정의: 7일(2,016봉) 최고치 갱신 → 12시간 이내 후보를 한 에피소드로 묶음 →
에피소드 최고 OI 를 고점 → 이후 관찰 구간의 **최저 OI 까지**가 낙폭.

에피소드 **31건** (관찰 완료 기준, 코인 수량 BTC):

| | 3일 관찰 | 7일 관찰 |
|---|---:|---:|
| 중앙 낙폭 | −6.39% | **−8.12%** |
| 25 / 75 백분위 | −8.30 / −4.79% | −9.26 / −6.01% |
| 3% 이상 | 28/31 (90%) | 31/31 (100%) |

**OI 가 중앙 8% 풀리는 동안 가격은 제자리였다.** 포지션 정리와 가격 방향은 별개다.

두 가지 한계를 반드시 함께 기록할 것:

1. **자명함 위험** — 6개월간 OI 가 80k~116k 레인지를 오갔다. 레인지 데이터에서
   "7일 고점 뒤 하락"은 발견이 아니라 산수에 가깝다. OI 가 추세적으로 쌓인 국면에서는
   전혀 다른 결과가 나올 수 있다.
2. **해소 고점 수준에 공통점 없음** — 91,812 ~ 115,680 BTC 전 범위에 흩어져 있다.
   **"OI 몇만까지 가면 풀린다"는 수준은 데이터에 없다.**

### 15-7. 이번 측정에서 저지른 방법론 오류 (재발 방지)

- **임계 통과 시점을 크기로 기록했다.** "−3% 해소"가 전부 −3.0x% 로 나온 것은
  발견이 아니라 측정 방식이 만든 값이었다. **임계값을 정하지 말고 분포를 보라.**
  실제 낙폭은 중앙 −8.12% 로 두 배 이상이었다.
- **연속 봉만 묶어 사건을 세었다.** 802 대 32, 25배 차이. 군집을 무시하면 표본이 부풀려진다.
- **체류 시간을 안 보고 비율만 봤다.** `~85,000` 구간 95.87% 는 56시간짜리 한 사건이었다.
